# Symphony 号池工作台

V1.3.0 · 支持 Windows 本机、Ubuntu 24.04 LTS 与本机 Docker 测试。Windows 安装步骤见[项目首页](../README.md)，Linux 服务器见 [Ubuntu 部署说明](docs/UBUNTU.md)，隔离测试见 [Docker 说明](docs/DOCKER.md)。

## 页面入口

默认地址为 `http://127.0.0.1:8787`。

| 路由 | 功能 |
| --- | --- |
| `/jobs` | 创建视频任务，查看生成进度和下载结果 |
| `/accounts` | 账号档案、登录窗口、只读验收和额度 |
| `/events` | 审计事件 |
| `/api-docs` | 合作方 API 文档及请求样例 |

根地址进入工作台。旧 `/overview`、`/video-api` 地址跳转到 `/jobs`。页面支持直接刷新、浏览器前进后退；菜单切换会保留尚未提交的表单。

## 接入账号

1. 在“账号池”新增账号，选择平台，核对自动填写的编号和名称。
2. 点击“打开登录窗口”，在该账号的独立浏览器中手动完成登录。
3. 关闭这个专用窗口，再点击“只读验收”。验收记录登录状态、可用模型及额度信息。
4. 账号就绪后可以参与派号。通过账号卡片编辑编号和名称；修改编号前先关闭专用窗口。

账号卡片右上角的删除图标会要求再次确认。删除后，该账号的浏览器登录档案一并清理；历史任务、视频和审计记录保留。正在验收，或仍有草稿、排队、生成中、需核对任务的账号不可删除，请先完成或取消这些任务并关闭登录窗口。

每个账号使用独立的 Chrome / Edge 持久化档案。浏览器窗口未关闭时会占用档案，验收或生成可能失败。账号密码和 Cookie 不写入工作台数据库；浏览器登录态仍属于本机私有数据。

Ubuntu / Docker 上每个账号使用独立的浏览器档案和 Xpra 会话。Windows 安装 Xpra 原生客户端并完成客户端配置后，从账号卡片打开登录页，点击首位的“直接打开 Xpra”。也可下载 `.xpra` 连接文件双击连接。登录完成后点击“登录完成，结束窗口”，再验收。仅断开客户端不会释放档案。安装器为 x86_64 选择 Chrome，为 ARM64 选择 Chromium。

Chrome 显示为 Windows 上的独立窗口，支持客户端剪贴板同步与窗口缩放。服务器上的管理页和连接网关通过 SSH 隧道访问；本机 Docker 仅映射回环端口。连接文件包含临时会话凭据，不要分享给其他人。

豆包额度根据当天可见作品粗估，可能无法读取，只用于派号排序。平台明确提示今日免费次数耗尽时，该账号冷却、额度置零；当天重新验收不会覆盖该提示，次日可重新验收恢复。TikTok 使用页面读取的积分检查任务消耗。

## 生成视频

1. 在“工作台”选择自动派号或指定账号，填写模型、时长、比例、并发数及正反提示词。
2. 可不上传图片直接生成，也可添加参考图片；PNG / JPG / WebP，每张最多 20 MB。
3. 点击“开始生成”上传素材并尝试启动。页面的并发数 N 表示使用 N 个不同账号，各生成一条视频；账号不足时整批不启动，保留任务供重试。
4. 完成后点击“下载 MP4”。“需核对平台”表示提交结果不明确；先核对平台记录，已有平台任务链接时可“重新收集结果”。

| 模型 | 平台 | 时长（秒） | 比例 | 图片数 |
| --- | --- | --- | --- | --- |
| Seedance 2.0 Fast | 豆包 | 5、10 | 9:16、16:9 | 0–9 |
| Seedance 2.0 Mini | 豆包 | 5、10 | 9:16、16:9 | 0–9 |
| Video 1.5 Pro | TikTok | 5、10、12 | 9:16 | 0–4 |

页面并发数为 1–8，大于 1 时须自动派号。TikTok 无图使用文字生成，单图使用图片生成，2–4 图使用参考素材生成；其当前网页入口没有比例控件，使用平台默认竖屏输出。负面提示词独立保存，执行时作为“请避免出现”的要求附加到平台提示词。

同一账号同时只运行一项任务。自动队列使用近期验收记录筛选兼容且空闲的账号，优先选记录额度较高的账号。额度耗尽时标记冷却并安全换号；提交前的浏览器故障会暂停该账号并尝试其他账号；已提交但结果不明确的任务进入核对状态，避免重复消耗。指定账号的任务不会擅自换号。

**页面并发数与合作方 API 的 `count` 不同：** `count` 是总条数，1–100；合作方任务每批最多两条，批次结束后提供结果并继续下一批。内部调度细节见[开发与维护](docs/DEVELOPMENT.md)。

## API 文档

| 使用场景 | 接口 | 文档 |
| --- | --- | --- |
| 合作方调用本号池 | `/v1` | [合作方 API 文档](PARTNER_API.md) |
| 同一机器的程序调用 | `/api/video-generations` 等 | [本机 API](VIDEO_API.md) |
| 工作台选用已有的第三方视频服务 | `/api/video-provider` | [可选上游接入](NOCSNOW_API.md) |

对外 API 支持共享 Bearer Key、任务防重、随任务上传图片、查询、取消、批次回调和签名下载。下载提供生成时保存的原始 MP4 字节，不进行转码；链接有效期、文件保留期和完整约束以合作方文档为准。

本机服务默认监听 `127.0.0.1`。未配置本机 `.env` 密钥时，对外 API 返回 503。公网域名与 HTTPS 回调地址须部署时配置。

## 数据位置

以下路径相对于本工作台目录；首次运行或对应功能使用时自动创建。

| 路径 | 内容 |
| --- | --- |
| `data/workbench.sqlite` 及同名辅助文件 | 账号、任务、调度、回调与审计数据 |
| `data/generated/` | 已保存视频 |
| `data/uploads/` | 任务参考图片等上传素材 |
| `logs/` | 启动与错误日志；空错误日志是正常情况 |
| `../<账号编号>_sandbox_data/` | 每个账号的私有浏览器档案 |
| `.env` | 本机 API 密钥及服务配置 |
| `.venv/` | 当前机器安装的 Python 依赖 |
| `.runtime/` | Ubuntu 安装器下载的 Node.js 运行环境 |
| `data/vnc.pass`、`data/desktop.Xauthority` | Ubuntu 远程桌面密码文件与显示认证文件 |

交付包排除以上内容，接收方从空数据开始。需要自行备份当前数据时，先停止服务并关闭专用浏览器，保存数据库、素材、视频与关联浏览器档案；更换安装路径时也需更新数据库中保存的绝对路径。

## 常见问题

- **启动失败：** 检查 Node.js 版本及 `logs/workbench.stderr.log`；端口默认 8787。
- **Python 或 Playwright 缺失：** 重新执行项目首页中的虚拟环境和依赖安装步骤。
- **档案被占用：** 关闭对应专用登录窗口，再验收或执行。
- **没有可用账号：** 检查账号是否就绪、模型是否已验收、验收是否过期，以及平台是否提示额度耗尽。
- **结果需核对：** 查看平台已有任务，必要时重新收集；不要直接重复创建同一业务任务。
- **合作方访问不到：** 本机地址只对当前机器有效；按合作方文档配置公网 HTTPS 接入。
- **网页自动化失效：** 平台页面更新可能需要调整执行器；真实平台行为不由本工作台保证。

Windows 停止服务运行 `.\stop-workbench.ps1`；Ubuntu 使用 `systemctl --user stop symphony-workbench`。测试及重新打包见[开发与维护](docs/DEVELOPMENT.md)。
